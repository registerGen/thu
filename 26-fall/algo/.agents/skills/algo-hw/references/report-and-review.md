# Report and review

## Skeleton

`report/report.tex` (from `assets/report/report.tex`) is the whole document; the
table and the figure arrive as generated snippets it `\input`s:

```latex
\input{table.tex}
\input{plot.tex}
```

Every `.tex` source keeps the `% vim:tw=80:` modeline on its first line and is
hard-wrapped at textwidth 80, `gq`-style: a line the editor could reflow is a
bug, and only a single unbreakable token such as a URL may stick out.

Preamble: `article`, `booktabs`, `enumitem`, `fancyhdr`, `geometry`,
`pgfplots`, `siunitx`, `unicode-math`, `hyperref` — and nothing unused (no
`graphicx`, `ulem`, `amsthm`, `thmtools` unless the write-up needs them). Build
with `latexmk -xelatex`; `unicode-math` rules out pdflatex.

Sections in order: title block, abstract, Algorithm Analysis, Experiment and
Results, Conclusion, AI disclosure.

- The **abstract** states the result: exponents, speed-up factors, crossover.
- **Algorithm Analysis** is the user's exposition. Fix errors in it (a wrong
  recurrence, a hand-wavy bound) and leave the voice alone.
- **Experiment and Results** says what was measured and how — release build,
  size ladder, input distribution, the 0.5 s repetition budget, and that every
  result was checked against the naive reference — then the table and figure.
- The **Conclusion** quotes measured numbers: growth per decade or per
  doubling, fitted exponents, the crossover, and the explanation for the one
  outlier the data shows.
- The **AI disclosure** lists every AI-written artifact (readme, CLI when the
  task has one, generator, tests, benchmark, plot/table scripts) plus "reviewed
  and improved this report". Reviewing the algorithm code is the author's own
  affair and is not listed. It links the skill that produced the work —
  `https://github.com/registerGen/thu/tree/main/26-fall/algo/.agents/skills/algo-hw`
  — noting that it is the author's own — and leaves the model name for the user
  to confirm. A theory write-up carries neither a disclosure nor the link.

## The two generators

`table.py` → `table.tex`: raw measurements, three significant figures,
`siunitx` `S` columns, dashes for sizes an algorithm did not run,
`\begin{table}[t]` with the caption **above** and a `\label`.

If the input size is not a single number, pass every size column
(`--size-columns n,m`): the table prints one column per dimension, labelled by
the column name, and the dashes still mark the combinations an algorithm did
not run.

`plot.py` → `plot.tex`: a `pgfplots` log-log axis, one `\addplot` per
algorithm, legend in the empty corner, `\begin{figure}[t]` with the
`tikzpicture` first and the caption **below** it, the caption ending in
`data from Table~\ref{tab:...}`. Both start with
`% Generated by ... -- do not edit by hand.` and take the CSV path as an
argument.

A log-log line plot needs one numeric, growing axis, so `plot.py` reads a
single size column (`--size-column`, default `n`) and refuses non-numeric
values with an explicit message. For a size that is a pair, either keep the
varying dimension in `n` and state the fixed one in the caption, or drop the
figure for that task and let the table carry the result.

When a figure or table is oversized for the page budget, change the generator,
rebuild and re-measure — never hand-edit the generated `.tex`.

## Review rubric

Read the report next to the CSV, then report five buckets:

1. **Technical corrections** — wrong recurrence or claim, unsupported
   statement; give the correct form and the numbers behind it.
2. **Claims worth making concrete** — quantify what the data supports: growth
   factors, fitted exponents, multiplication counts against wall-clock,
   crossover points, the explanation of an outlier.
3. **Language** — line-referenced wording fixes.
4. **Presentation** — caption placement, unused packages, float placement,
   page gaps, axis titles that duplicate the caption, figure size.
5. **AI disclosure** (reports only — a theory write-up has neither a disclosure
   nor a link to the skill) — must name every AI-written artifact, state that
   the report was reviewed and improved, and cite the skill that produced it:
   `https://github.com/registerGen/thu/tree/main/26-fall/algo/.agents/skills/algo-hw`,
   saying it was written by the same author as the homework. It does not
   mention reviewing the algorithm code.

When the review covers a theory write-up, `theoretical.tex` is never edited:
the findings and the proposed corrections go into the manifest and the author
applies them.

Then apply the mechanical *and* analytical improvements and publish a manifest:
a before → after table of every edit, the recomputation behind each changed
number, and the items deliberately left alone with the reason. The user reviews
the manifest, not the diff.

## Number audit — your standing duty

Every number must come from the CSV, the code, or a calculation stated next to
it. Run this yourself after measuring, after every report edit and before
packing — the user should never have to ask:

```bash
python3 <skill>/scripts/audit.py numbers report/report.tex   # numbers + context
python3 <skill>/scripts/audit.py stats   report/bench.csv    # what the data supports
```

Check each reported number against the recomputed set, rounding the way the
report does, and flag anything that only matches after generous rounding.
Catches from previous homeworks: a growth factor quoted as 100.2 when the data
gives 100.1; a ratio computed from already-rounded inputs while the exact ratio
rounds the other way; an extrapolated runtime presented as measured; a
percentage truncated instead of rounded; "3.5 minutes" where the 7× projection
says 3.3.

Also verify the visuals: every `\addplot` coordinate and every table cell must
equal its CSV value after the documented rounding, and dashes must sit exactly
where a row is missing.

## Page budget

Two pages is the target. After editing, rebuild and read the page count from
the log; if the conclusion or the disclosure spills, adjust the figure size in
`plot.py`, the caption length, or the float specifiers, and state the verified
page count.
